# Google Analytics 4 — consent banner, 30 October 2026

The user supplied G-JXHZ3W8WHP, requested manual installation and then explicitly requested an Analytics acceptance banner. The public measurement ID is retained. The unconditional head snippet was removed from index.html. src/analytics.ts now performs its one async loader/config only after explicit acceptance or a valid remembered acceptance. src/AnalyticsConsent.tsx provides the consent controls in Spanish, English and French.

Before a choice, after rejection, or with missing/invalid/expired storage, our integration does not fetch gtag.js, send Analytics events or send denied-consent measurement pings. On acceptance it queues analytics_storage default denied, update granted, js and one config, then appends the async SDK with data-cfasync=false. React StrictMode and repeated acceptance cannot add a second SDK/config. Full-page navigation continues to use the normal GA4 page view per accepted page load; no extra React page-view tracker.

Accept and Reject are equally available, without a preselected choice. The local record fansgta:analytics-consent:v1 contains the choice and its savedAt timestamp, valid for 180 days. On returning after expiry, the banner asks again. Expired records are also rechecked when a page becomes visible. There is no migration of unrelated advertising preferences into Analytics consent. An old _ga cookie is not consent: accessible root-path _ga cookies are removed while Analytics is blocked. If local storage is unavailable, an explicit choice applies in memory to the current page; a visible notice explains that it cannot be remembered for another visit.

Visitors can reopen the choice from Analytics preferences in the footer or the Cookies page. Withdrawing acceptance sets the property disable flag, clears accessible root-path _ga cookies for host/parent domains and reloads the document to discard the executed SDK/listeners. The reload reads rejection before loading any Analytics code. Storage events synchronize changes to other open tabs, including withdrawal. The control does not erase historical Google data, cancel already completed requests or promise deletion of inaccessible third-party storage.

This banner controls Analytics. AdSense verification code and ads.txt are unchanged; Adsterra remains paused and popunder disabled. YouTube keeps its separate existing media preference. Advertising/security rules, account settings, subscriptions and the daily editorial schedule are unchanged. This is not represented as a Google-certified advertising CMP or universal legal-compliance certification. No paid product or external consent service was activated.

Privacy/cookies text now describes the actual optional loading, choice lifetime and withdrawal. No custom names, emails or passwords are added to Analytics parameters. Automatic SDK collection after acceptance depends on Google's implementation/account settings. Installation and mocked tests do not demonstrate account ownership, Realtime receipt, consent-law compliance, AdSense approval or ad fill.

Primary technical reference checked: https://developers.google.com/tag-platform/security/concepts/consent-mode (basic mode blocks tags before acceptance, unlike advanced denied-mode pings). No advertising consent categories are changed by our analytics_storage setting.
